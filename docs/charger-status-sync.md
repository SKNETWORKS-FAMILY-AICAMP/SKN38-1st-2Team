# 전국 충전기 상태 수집

`jobs/poll_charger_status.py`는 한 번 실행할 때 전국 상태 변경분을 읽습니다. `getChargerStatus`의 `zcode`를 생략하고 `period=10`으로 조회합니다. 5분마다 실행하면 인접 조회 구간이 약 5분 겹칩니다. 한 번의 실행에서 모든 응답 페이지를 순서대로 읽으므로 실제 호출량은 로그의 페이지 수로 확인합니다. [한국환경공단 상태 API](https://www.data.go.kr/data/15076352/openapi.do)

## 배포 PC 설정

1. MySQL과 웹을 실행하는 Windows PC에서 스케줄러 실행 계정의 환경변수 `EV_CHARGER_SERVICE_KEY`를 설정합니다. 같은 계정에 `mysql_config_editor`로 MySQL 로그인 경로를 설정합니다. 기본값은 `evlocal`과 `ev_infra`입니다. `EV_MYSQL_EXE`, `EV_MYSQL_LOGIN_PATH`, `EV_MYSQL_DATABASE`로 변경할 수 있습니다. DB 계정에는 충전기·상태 조회, 상태 테이블 INSERT·UPDATE, 임시 테이블 생성 권한이 필요합니다.
2. 프로젝트 루트에서 `python -m jobs.poll_charger_status`를 실행해 키, 응답 페이지 수, MySQL 저장을 확인합니다. 수집기의 기본 API 호출 상한은 한국 시간 기준 하루 900회입니다. 운영 한도에 맞춰 `--daily-budget`을 조정할 수 있습니다. 페이지 요청은 실패하더라도 수집기 호출 예산에 포함합니다.
3. **Windows 작업 스케줄러**에서 아래 예시로 작업을 만듭니다. PC에서 실행하는 Python 환경에 `requirements.txt` 의존성을 설치합니다.

| 설정 | 값 |
|---|---|
| 트리거 | 한 번 시작한 뒤 5분마다 반복, 기간은 무기한 |
| 프로그램 | 배포 PC의 Python 실행 파일 전체 경로 |
| 인수 | `-m jobs.poll_charger_status` |
| 시작 위치 | `app.py`가 있는 저장소 전체 경로 |
| 일반 | 사용자 로그온 여부와 관계없이 실행 |
| 중복 실행 | 기존 작업이 실행 중이면 새 인스턴스를 시작하지 않음 |

웹과 작업이 다른 Windows 계정으로 실행되면 웹 계정에 수집 상태 파일 읽기 권한을 부여합니다. 기본 상태 파일은 `.local/charger_status/sync.json`이고 로그는 같은 위치의 `sync.log`입니다. 다른 위치를 사용하려면 두 프로세스에 같은 절대경로 `EV_CHARGER_SYNC_STATE`를 설정합니다.

## 상태 반영과 수집 공백

- 응답에 페이지 정보가 있으면 총 건수와 페이지 크기를 검증합니다. `items`만 반환되면 빈 목록까지 조회합니다. 페이지가 반복되거나 20페이지 안에 종료를 확인하지 못하면 해당 실행의 변경분은 DB에 반영하지 않습니다.

- `statId + chgerId`별로 가장 최신 상태를 남깁니다. 이미 저장한 같은 상태와 오래된 응답은 건너뜁니다. 동일 시각에 서로 다른 상태가 수신되면 충돌한 상태로 덮어쓰지 않습니다. 초기 적재본과 상태·변경 시각이 일치하고 API 관측 시각이 비어 있으면 최초 관측 시각을 기록합니다.
- 페이지 사이 응답 건수가 바뀌면 로그에 남깁니다. 다음 실행의 겹치는 구간에서 다시 확인합니다. 페이지 실패나 일일 예산 소진 시 이전 성공 시각을 유지합니다.
- Streamlit은 상세를 열거나 **저장 상태 다시 읽기**를 누를 때 MySQL에 저장된 상태를 읽습니다. 전국 수집 시각, 충전기별 관측 시각, 수집 지연과 기록된 공백을 표시합니다.
- 이 API는 최근 변경분을 제공합니다. 첫 실행에서 초기 CSV 이후의 전체 상태를 복구하거나 10분 이상 끊긴 구간을 재수집하려면 별도의 상태 스냅샷 확인이 필요합니다.
