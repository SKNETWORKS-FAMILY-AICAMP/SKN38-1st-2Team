# 전기차 충전 인프라 지도 개발 회고

이 문서는 프로젝트의 초기 구상부터 실데이터 연결, 배포 PC의 예약 작업 검증까지 진행한 수정과 시행착오를 정리합니다. 운영 구성과 현재 화면 사용법은 [README](../README.md)에 있고, 아래에는 **왜 바꿨는지, 무엇으로 확인했는지, 어떤 작업이 남아 있는지**를 기록했습니다. 충전기 상태 수집의 검증 기록은 2026년 11월 8일 한국 시간 기준입니다.

## 1. 프로젝트 범위와 데이터 선택

처음에는 지역별 전기차·전기이륜차 등록대수와 충전소 수를 비교하는 지도를 구상했습니다. 이후 전기이륜차를 제외하고, 자동차 등록 규모와 충전 인프라를 비교하는 화면과 실제 충전소를 찾는 화면으로 범위를 좁혔습니다.

초기에는 샘플 데이터로 전국 → 시도 → 시군구 → 충전소 상세의 클릭 흐름을 검증했습니다. 실제 데이터로 전환한 뒤에는 충전소 기본정보와 등록통계를 MySQL에서 읽고, 수시로 바뀌는 충전기 상태만 예약 작업으로 갱신했습니다. 카카오는 주소 좌표 변환과 주변 카페 조회에 사용했습니다. API 호출이 지도 이동과 상세 조회를 매번 지연시키는 구조를 피하고, 어떤 값이 원본 스냅샷에서 왔는지 구분할 수 있게 했습니다.

## 2. 지도 화면의 반복 수정

| 겪은 문제 | 검토와 수정 | 결과 |
| --- | --- | --- |
| 지역을 누를 때 네모 표시가 어색하고, 시군구 화면에서 전 세계 지도가 보였습니다. | 각 단계가 같은 경계를 쓰도록 WGS84 GeoJSON을 사전에 SVG 경로로 변환했습니다. 지도 이미지를 단계마다 저장하는 방식도 검토했지만 경계와 마커를 함께 조작할 수 있는 SVG를 선택했습니다. | 전국에서 지역으로 들어갈 때 같은 도형의 `viewBox`를 보간해, 클릭한 지형이 그대로 확대되는 효과를 냈습니다. |
| 지역 클릭 반응이 느려 페이지 리디렉션인지 의심했습니다. | 화면 동작과 서버 조회를 분리했습니다. 지도 이동과 지역 자동완성은 브라우저에서 처리하고, 처음에는 집계와 경계만 내려보냅니다. 시군구에 들어갈 때 해당 지역의 충전소를 읽습니다. | 도형 이동이 서버 조회와 분리됐습니다. Streamlit 컴포넌트는 같은 화면을 유지하며 요청 ID로 조회 결과를 연결합니다. |
| 시군구에 들어가도 확대가 부족하거나, 선택한 구만 보이면서 서울 외곽과 인접 구가 사라졌습니다. | 선택 구 경계에 여백을 주고 해당 시도의 다른 구와 외곽선을 계속 그렸습니다. 선택 구는 테두리를 강조하고 인접 구도 클릭할 수 있게 했습니다. | 시군구 범위에서 옆 구가 화면에 일부 보이면 한 번 눌러 바로 이동할 수 있습니다. 서울의 25개 구에도 같은 규칙을 적용했습니다. |
| 도에서 군을 클릭하면 기존 색이 사라졌고, 지역명이 지도 위에 겹쳤습니다. | 지역을 선택해도 시도 내 시군구 색 범위를 유지하도록 바꾸고, 지역명은 마우스를 올릴 때 공급 등급 또는 충전기 수와 함께 표시했습니다. | 선택 전후의 경계와 색을 비교할 수 있고, 충전소 이름과 상세주소는 지도 위 라벨과 상세 패널에서 확인합니다. |
| 충전소가 촘촘하게 찍혀 위치를 읽기 어려웠습니다. | 화면에서 가까운 마커를 묶어 숫자로 표시했습니다. 숫자 마커나 **충전소 주변 보기**로 추가 확대할 때 OpenFreeMap 도로 타일을 불러옵니다. | 동 단위 행정구역 화면을 추가하지 않고도 도로를 기준으로 위치를 파악할 수 있습니다. 도로 타일을 기다리는 동안 SVG 경계와 마커가 표시됩니다. |
| 확대 이동 중 녹색 지도 화면이 다시 나타나는 것처럼 보였습니다. | 확대 화면 사이에서 MapLibre 지도 인스턴스를 재사용하고, SVG 카메라가 이동할 때 같은 프레임에 도로 지도 카메라를 맞췄습니다. | 브라우저 검증에서 도로 레이어 재사용과 마커·도로의 위치 정렬을 확인했습니다. |
| 추가 확대 상태에서 바탕을 누르면 시군구로 돌아갔고, 축소 경로가 분명하지 않았습니다. | 클릭 좌표를 SVG 좌표로 변환해 배율을 유지한 채 중앙으로 옮깁니다. 시군구 전체 보기로 돌아가는 동작은 **한 단계 뒤로**에 연결했습니다. | 확대 상태에서 지역 바탕을 눌러도 같은 시군구에서 이동할 수 있습니다. 미니맵은 현재 위치를 보여줍니다. |
| 상세가 지도 아래에 잘렸고, 옆 패널로 바꾼 뒤에도 마커를 누를 때 확대 배율이 달라졌습니다. | 데스크톱 상세를 지도 오른쪽에 배치하고 패널 내부 스크롤·마우스 드래그를 추가했습니다. 상세를 열면 좁아진 지도 영역에 맞춰 보이는 범위를 줄이고 중심과 배율을 유지합니다. | 데스크톱·모바일 너비에서 상세 열기와 닫기 후 배율을 확인했습니다. 표시 문구도 **MySQL 충전소 정보**에서 **충전소 정보**로 바꿨습니다. |

## 3. 검색·즐겨찾기와 실제 충전소 상세

- **지역과 도로명주소 검색.** `강`처럼 일부만 입력해도 지역명을 가나다순으로 제안합니다. 서울과 부산의 강서구처럼 이름이 같은 곳은 시도를 붙여 구분합니다. 충전소명·도로명주소·ID 검색도 추가했습니다.
- **빈 검색창의 주변 찾기.** 입력이 없을 때는 **내 주변 충전소 찾기**를 보여줍니다. 사용자가 고른 도로명주소의 좌표를 기준으로, 시군구 경계를 넘어 직선거리순 최대 5곳을 찾습니다. 카카오 키가 없을 때는 DB에 등록된 충전소 주소를 기준점 후보로 사용할 수 있습니다. DB에서는 후보 좌표 범위를 넓혀가며 `ST_Distance_Sphere`로 거리를 계산합니다.
- **별명과 즐겨찾기.** 지역 또는 충전소를 주소와 함께 저장하고 별명을 붙여 왼쪽 패널에서 다시 열 수 있게 했습니다. 저장 위치는 브라우저 `localStorage`입니다.
- **여러 충전기의 사용 가능 대수.** 같은 충전소에 충전기가 여러 대인데 상세 집계가 빠지거나 한 대만 보이는 문제를 확인했습니다. `stat_id`로 소속 충전기를 모두 조회하고, `stat_id + chger_id`로 상태를 연결해 상태코드 `2`를 사용 가능으로 합산합니다. 급속·중속·완속은 정격출력 구간으로 나눕니다.
- **상세에서 필요한 실제 이용조건.** `parkingFree`, `limitYn`, `limitDetail`을 표시하고, 상태 변경 시각(KST)과 API 관측 시각(UTC)을 초 단위로 구분했습니다. 시간 뒤의 `.000000`은 제거했습니다.
- **주변 카페 API 연결.** REST 키를 서버 설정으로 옮기고, 사용자가 요청할 때 충전소 좌표 주변 300m 이내 카페를 거리순 최대 10곳으로 조회합니다. 초기 적재한 공공데이터 카페 테이블은 별도 자료로 보존합니다.

## 4. 엑셀 추출과 MySQL 적재

### 전기차 등록 비중의 분모 검증

월별 파일의 10번 시트에서 ‘전기’부터 다음 연료 구간 전까지 떼어 월별 시트로 모으는 방식을 검토했습니다. 웹에서 월별 추세를 읽기 위해서는 기준월과 지표가 행으로 정리된 CSV와 DB 테이블이 더 적합해, 전국 월별과 시도 월별 데이터를 분리했습니다.

`total_count`를 확인하는 과정에서 01번 시트에는 **전체 차종 총계**, **승용차 전체**, **승용차 관용·자가용·영업용**이 각각 있다는 점이 중요했습니다. 전국 전기 승용차 비중은 10번 시트의 **비사업용 전기 승용차 ÷ 전체 비사업용 승용차**로 계산하고, 분모를 01번 시트의 승용차 관용과 자가용의 합으로 대조합니다. 시도 공급 등급에는 10번 시트의 전기 자동차 차종 전체 등록대수를 사용합니다. 두 데이터의 분모가 다른 이유를 README에도 기록했습니다.

### 한글, 선행 0, 좌표와 코드

| 발견한 문제 | 대응 |
| --- | --- |
| CSV를 열었을 때 한글 파일명이 깨져 보였습니다. | 원본 CSV는 UTF-8로 읽고 BOM이 있는 파일도 같은 경로에서 처리했습니다. DB는 `utf8mb4`로 연결해 파일 인코딩과 조회 프로그램의 표시 인코딩을 구분했습니다. |
| `chgerId=01` 같은 값이 숫자로 변환되면 상태와 연결할 수 없습니다. | 충전소 ID·충전기 ID·행정코드를 문자형으로 저장하고 선행 0을 보존했습니다. |
| 충전소 이름과 주소, 지역코드, 좌표가 항상 일치하지 않았습니다. | 주소만 보고 좌표를 덮어쓰는 방식을 보류했습니다. 원본 코드와 좌표를 보존하고, 좌표가 들어가는 폴리곤과 원본 코드의 일치 여부를 충전소별로 기록했습니다. |
| 등록통계의 지역코드가 SVG 경계와 다르거나 하나의 집계가 두 시도에 걸쳤습니다. | 별도 매핑표를 두었습니다. 전북 코드 차이를 연결하고, **전남광주** 합산 행은 두 경계에 표시하되 전국 합계에는 한 번만 반영했습니다. |

초기 검증에서 충전소 102,213곳 중 **101,355곳**을 지도에 연결했습니다. 나머지 **858곳**은 시군구 코드와 좌표 불일치 294곳, 시도 불일치 279곳, 경계 밖 273곳, 경계 중첩 11곳, 원본 코드 충돌 1곳입니다. 해당 위치의 지도 코드를 비워 마커와 거리 추천에서는 제외하고, 이름·주소·ID로 상세는 조회할 수 있게 했습니다.

Windows에서 MySQL CLI가 바로 실행되지 않아 설치 경로와 `mysql --version`을 확인한 뒤 `mysql_config_editor`의 로그인 경로를 사용했습니다. 적재는 헤더·해시·키·행 수를 먼저 검사하고 스테이징 테이블에서 조인을 검증한 뒤 서비스 테이블로 전환했습니다. 총 9개 테이블에 충전소 102,213곳, 충전기와 초기 상태 각 529,359행, 카페 113,440행 등을 적재했습니다. ## 5. 공급 등급과 등록통계 크롤링

- **상대 색상에서 고정 등급으로.** 지역을 정렬해 상대적으로 혼잡해 보이게 하는 방식에서, 등록 전기차 한 대당 공용 충전 정격출력(kW/대)을 비교하는 방식으로 바꿨습니다. 미삭제·이용제한 없음·양수 출력 조건으로 공급을 집계합니다. 매우 부족·부족·보통·충분·여유의 경계는 1.3·3.0·5.0·8.0 kW/대입니다. 1.3은 EU AFIR의 경량 배터리 전기차 기준을 참고했고, 나머지는 프로젝트에서 정했습니다. 시군구는 등록 분모가 없어 충전기 수로 표시합니다. [지표 정의와 출처](../README.md#2-데이터와-지표)
- **크롤링의 역할.** 국토교통부 통계누리 HTML에서 공개된 월별 첨부파일을 찾고, 표시 이름과 실제 서버 파일명을 함께 읽어 다운로드 URL을 구성합니다. 다운로드한 엑셀은 시트와 월을 검증하고 해시로 보관합니다. 2026년 7~9월 엑셀과 기존 MySQL 적재본의 비교 항목 54개가 일치했습니다.
- **월별 자동 적재.** 배포 PC가 하루 한 번 신규 월을 확인하고 기준월 연속성, 01·10번 시트 합계, 지역코드가 맞을 때 전국·시도 두 테이블을 한 트랜잭션으로 저장합니다. 신규 월이 없으면 정상 종료합니다. 실행 인수는 `-m jobs.crawl_registrations --sync-new`입니다. [크롤러 운영 문서](registration-crawler.md)

## 6. 충전기 상태 수집의 시행착오

### 상세 클릭 호출에서 전국 예약 수집으로

처음에는 충전소 상세를 열 때 저장된 상태가 10분 이내면 보여주고, 오래됐으면 API를 호출해 갱신하는 방식을 검토했습니다. 이 방식은 상세를 열 때 외부 응답을 기다리고, 사용자가 방문하지 않은 충전소는 갱신되지 않습니다. 이후 지역코드별 전수 요청과 전국 단일 호출을 검토했습니다. 전국은 한 번의 요청으로 모든 행이 오지 않으므로 **5분마다 최근 10분 전국 변경분을 페이지로 수집**하는 방식으로 정했습니다.

인접 실행의 약 5분을 겹치게 하고, 충전기 키와 변경 시각으로 중복을 제거합니다. 중복 응답은 최신 변경만 반영하며 오래된 응답이나 같은 시각의 상충 상태로 기존 값을 덮어쓰지 않습니다. 상세는 저장된 상태를 읽습니다. 최근 10분보다 긴 수집 공백의 복구에는 별도 스냅샷 확인이 필요합니다. [수집 설계와 운영](charger-status-sync.md)

### 2026년 11월 8일 장애 추적

| 화면이나 로그에 나타난 현상 | 확인한 내용과 조치 |
| --- | --- |
| 작업 스케줄러의 **기록(사용 안 함)**과 `0x41303`, 마지막 실행 시간이 1999년으로 표시 | 작업 기록을 켠 뒤 마지막 실행 결과와 상태 로그를 나눠 확인했습니다. `0x41303`은 아직 실행 결과가 기록되지 않은 상태였습니다. |
| 두 작업이 `0x0`으로 보였지만 충전기 로그와 DB 관측 시각이 없었음 | 작업 스케줄러의 종료 코드와 어떤 Python 명령이 실행됐는지를 각각 확인했습니다. 월별 크롤러는 신규 자료가 없어도 `0x0`으로 종료하므로 그 코드만으로 충전기 수집을 검증할 수 없었습니다. |
| 충전기 작업이 `0x2`로 종료 | 예약 작업을 직접 조회한 결과, 충전기 명령에 월별 크롤러 전용 `--sync-new`가 붙어 있었습니다. 이를 빼고 `-m jobs.poll_charger_status`로 설정했습니다. Conda 환경의 `python.exe`와 프로젝트 루트 시작 위치는 유지했습니다. |
| 인수를 바꾼 뒤 `0x1`로 종료 | `sync.log`에 페이지 정보 오류가 찍혔습니다. 실제 API는 HTTP 200과 결과 코드 `00`으로 상태를 반환했고, `body` 안에 `items`만 있었습니다. `totalCount`, `numOfRows`, `pageNo`를 필수로 변환하던 코드가 여기서 실패했습니다. |
| 첫 페이지가 9,999행으로 가득 참 | 실제로 2페이지에서 다른 행을 받았고, 3페이지에서 빈 목록을 받았습니다. 메타데이터가 없을 때는 빈 목록까지 순회하고, 행 순서가 달라도 동일한 페이지가 반복되면 실패하도록 수정했습니다. 20페이지 내에 종료를 확인하지 못한 경우도 같은 실행을 실패 처리합니다. |
| 코드 수정 후 조회와 적재를 검증 | 페이지 순회 모의 검증을 포함한 Python 테스트 13개가 통과했습니다. 읽기 전용 API 검증에서는 15,604행과 종료용 빈 페이지를 확인했습니다. 오후 5:28 예약 작업 수동 실행은 `0x0`으로 종료했고, 로그에는 15,973행 수신, DB에는 15,733대의 API 관측 시각이 기록됐습니다. 오후 5:30과 5:35 자동 실행도 각각 수집 완료 로그가 남았습니다. |

수신 행은 API가 보낸 변경 후보입니다. DB 기록은 기존 충전기와 키가 일치하고, 변경 시각이나 첫 관측 조건을 만족한 결과입니다. 두 수치는 같은 실행에서도 다를 수 있습니다. 장애 확인에는 작업 스케줄러의 **종료 코드**, `sync.log`의 **수집 완료**, MySQL의 **관측 시각** 세 가지를 함께 사용했습니다.

## 7. 저장소 정리와 후속 작업

프로젝트를 `components/`, `services/`, `jobs/`, `db/import/`, `data/`, `docs/`로 나눴습니다. 실제 적재본을 기반으로 한 발표용 표본은 `data/sample/`에 두고, 인증 설정과 원본 적재 패키지, 로그는 로컬에서 관리합니다. README는 워크플로와 MySQL ERD를 포함한 발표 순서로 개편했고, 두 다이어그램을 PPT에 삽입할 수 있도록 SVG로 저장했습니다.

| 후속 범위 | 현재까지 확인한 상태 |
| --- | --- |
| 지도와 추천 목록의 이용제한 표시 | **제한 충전소도 두 화면에 포함하고 제한 여부를 표시**하기로 결정했습니다. 현재 제한 여부는 상세에서 확인합니다. 지도 마커와 추천 목록에 표시하는 변경은 남아 있습니다. |
