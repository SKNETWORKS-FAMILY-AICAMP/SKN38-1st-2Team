# MySQL 스키마 정리 계획

현재 구조와 테이블 관계는 [워크플로 및 ERD](workflow-erd.md)에 정리했습니다. 다음 단계에서 운영 DB의 실제 정의를 기준으로 별도의 `db/schema/`를 구성합니다.

| 단계 | 계획 |
|---|---|
| 기준 스키마 확정 | `SHOW CREATE TABLE`로 9개 테이블의 타입, 기본키, 유니크키, 인덱스와 문자셋을 기록합니다. 현재 적재기의 내장 정의와 대조하고 MySQL 8.0에서 재현 가능한 초기 DDL로 정리합니다. |
| 마이그레이션 구성 | 신규 환경 초기화용 DDL과 기존 환경 변경용 버전별 마이그레이션을 분리합니다. 기존 운영 DB에는 버전 확인과 사전 검사 이후 적용합니다. |
| 관계 제약 검토 | `charging_station`–`charger`, `charger`–`charger_status_latest`, `charging_station`–`station_region_map`의 누락 참조를 검사합니다. 삭제 정책과 적재 순서를 합의한 뒤 물리 외래키 추가 여부를 결정합니다. 지역코드 집계와 카페 좌표 검색은 논리 관계로 관리합니다. |
| 데이터 적용 검증 | 빈 테스트 DB에서 스키마를 만든 후 승인된 원본 스냅샷을 적재하고 테이블별 행 수, 키, 조인, 선행 0, UTF-8을 검증합니다. 신규 월 적재의 트랜잭션과 중복 방지도 확인합니다. |
| 후속 데이터 모델 | 좌표와 지역코드 정정은 원본 `stat_id`별 승인값, 근거, 출처를 별도로 저장하는 구조를 검토합니다. 미확인 858곳의 처리는 별도 검토 과정으로 유지합니다. |

현재 저장소의 `db/import/load_mysql.py`는 기존 스냅샷 적재를 재현하기 위해 내장 테이블 정의를 사용합니다. 독립 DDL과 마이그레이션 작성은 위 절차를 따른 후속 작업입니다.
